# Calibre에서 OCR·번역·EPUB 후편집을 분리하는 운영 흐름

전자책 작업은 OCR, 번역, 레이아웃 후편집을 한 단계로 묶으면 오류 원인을 찾기 어렵다. 실제 프로젝트 원본은 세 단계를 분리하고, 결과물을 새 책으로 등록하는 흐름을 취한다.

## 1. OCR

이미지 EPUB의 OPF/spine 순서를 기준으로 페이지를 읽고 OCR한다. MLX 서버, PaddleOCR, Tesseract 가운데 실행 가능한 engine을 선택할 수 있으며, 작업은 Calibre의 백그라운드 큐에서 실행한다.

원본 EPUB은 유지하고 `책 제목 - OCR` 이름의 새 EPUB을 만드는 것이 기본값이다. 진행창을 닫아도 작업은 계속되며, 현재 페이지가 끝난 뒤 취소할 수 있다.

## 2. 번역과 검수

OCR 텍스트는 바로 최종본으로 간주하지 않는다. 페이지별 인식 오류, 세로쓰기 순서, 루비와 표·말풍선 등을 검수한 뒤 번역한다. OCR engine과 번역 engine은 분리해 어느 단계에서 오류가 생겼는지 추적할 수 있어야 한다.

## 3. 방향·레이아웃 후편집

가로쓰기/세로쓰기 변환은 번역이 아니다. EPUB의 목차·본문 범위, CSS 방향, ruby/rt 후리가나 보존을 조정하고 결과를 새 책으로 등록한다.

```text
원본 EPUB
  → OCR EPUB
  → 검수·번역본
  → 방향/CSS 후편집본
```

## 결론

원본을 덮어쓰지 않고 단계별 산출물을 분리하면 실패한 OCR 페이지나 잘못된 번역을 되돌리기 쉽다. 또한 후편집 플러그인이 언어적 의미까지 바꾸지 않으므로 번역 품질과 레이아웃 품질을 독립적으로 검증할 수 있다.
