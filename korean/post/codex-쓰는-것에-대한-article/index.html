한 줄 요약

Codex를 잘 쓰는 핵심은 "큰 요청"이 아니라 "검증 가능한 작은 단위 작업"으로 지시하고, 매 단계 결과를 확인하는 것입니다.

Codex가 잘하는 일

  1. 반복적인 코드 수정
  2. 에러 로그 기반 원인 추적
  3. 문서/설정 파일 정리
  4. 테스트 보강 및 리팩토링 초안 작성

요청을 잘 쓰는 방법

1) 목표와 범위를 먼저 고정

  • 좋은 예: "content/korean/post의 문서 스타일을 통일하고 front matter를 정리해줘"
  • 나쁜 예: "전체 프로젝트를 알아서 개선해줘"

2) 완료 조건을 명시

  • 어떤 파일이 바뀌어야 하는지
  • 어떤 테스트/빌드가 통과해야 하는지
  • 어떤 것은 건드리면 안 되는지

3) 제약사항을 함께 전달

  • "Git commit/push는 하지 말 것"
  • "기존 UI 스타일 유지"
  • "한국어 문체로 작성"

실무 루틴 (권장)

  1. 요구사항 1~2문장으로 확정
  2. Codex가 관련 파일 탐색
  3. 작은 단위로 수정
  4. 빌드/테스트 실행
  5. 변경 파일과 핵심 차이 확인

이 흐름으로 가면 변경 이유와 결과를 추적하기 쉽습니다.

자주 발생하는 실패 패턴

  1. 요청 범위가 너무 큼
  2. "왜"보다 "무엇"이 불명확함
  3. 검증 단계 없이 대량 수정
  4. 기존 코드 스타일/관례를 무시한 변경

협업 팁

  • 파일 경로를 직접 지정하면 정확도가 올라갑니다.
  • "이 파일만", "이 함수만" 같은 제한을 주면 불필요한 변경이 줄어듭니다.
  • 먼저 초안 작성 후, 2차로 문체/구조 정리를 요청하면 품질이 좋아집니다.

예시 요청 템플릿

1목표: 로그인 API의 401/403 처리 정리
2범위: src/auth/*
3조건: 기존 응답 스키마 유지, 테스트 추가
4제외: DB 스키마 변경 금지, git commit 금지

정리

Codex는 "한 번에 완성"보다 "짧은 반복"에서 가장 강합니다. 작업 단위를 잘게 나누고, 완료 조건을 명확히 주면 실무 생산성이 크게 올라갑니다.
